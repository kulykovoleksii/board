# Рішення власника та напрям розвитку

Цей файл призначений для спільного оновлення власником і ШІ. Не стирати ручні записи під час актуалізації документації. Рішення описують потрібну поведінку; факт їх реалізації потрібно підтверджувати окремо.

## Підтверджені вимоги

### D001 — Жива документація для роботи ШІ

- Дата: 2026-09-10.
- Статус: погоджено власником.
- Джерело: запит створити Markdown-документацію в `docs` для подальшої роботи ШІ; власник також оновлюватиме її.
- Рішення: зберігати огляд, правила роботи, карту системи, обмеження та окремий журнал рішень у `docs`.
- Наслідок: наступні зміни мають зберігати ручні доповнення та підтримувати документацію актуальною.

## Питання без зафіксованого рішення

Це теми для майбутніх задач, а не вимога відповісти перед будь-якою роботою:

- Який основний напрям продукту: LMS, дошка оголошень або їх поєднання?
- Який доступ мають instructor/student, хто створює та публікує курси?
- Який сценарій запису, оплати, проходження, quiz та сертифікації потрібен?
- Які матеріали доступні гостям і які потребують активного enrollment?
- Чи залишаються оголошення, банери та старі auth/payment сценарії?
- Які мова UI, цільове середовище deployment і стандарт тестової БД?
